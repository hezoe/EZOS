EZOS インストールマニュアル

新しいサーバー（VPS）に EZOS を導入し、公開ドメインで使えるようにするための手順書です。GitHub から誰でも自分の環境を構築できます。

この手順は Claude Code に実行させることを前提に書かれています。作業者はサーバーへ SSH ログインし、Claude Code を導入・認証したうえで「このリポジトリ(github.com/hezoe/EZOS)をインストールして」と指示するだけで、Claude が本書を読みながら対話的に導入できます。手動で行う場合もそのまま実行できます。

構成の概要

各インストールは 1 つの Node アプリ + systemd サービス + Caddy のサイト定義 で成り立ちます。

ブラウザは Caddy（TLS 終端・リバースプロキシ）を経由して、localhost で待ち受ける Node アプリへ繋がります。ターミナルは node-pty + tmux で擬似端末に橋渡しされ、その中で claude が対話実行されます。

STEP 0. 事前に決める項目

環境依存で勝手に決められない値です。埋まるまで先に進まないでください（#3・#6〜#9 は既定のままで可）。

#項目例 / 既定用途
1サーバーのグローバル IP160.16.105.64DNS がここへ向いているかの確認
2公開ホスト名(URL)https://ezos.ezoe.netCaddy のサイト名 / WebAuthn origin
3WebAuthn の rpID(親ドメイン)ezoe.netパスキーの有効範囲
4DNS 設定は完了しているか済 / これから未なら A レコードを #1 の IP へ
5最初にパスキーを登録する端末作業者のノート PC(Chrome)その端末のブラウザで登録
6systemd サービス名ezos既定でよい
7localhost 待受ポート3100既定でよい
8設置ディレクトリ/home/debian/EZOSリポジトリを置く場所
9実行ユーザーdebiansystemd の User= 等

以降のコマンドはプレースホルダを次のように置き換えます。

HOST=ezos.ezoe.net            # #2 のホスト名(スキームなし)
ORIGIN=https://ezos.ezoe.net  # #2 のURL
RPID=ezoe.net                 # #3
PORT=3100                     # #7
SERVICE=ezos                  # #6
APPDIR=/home/debian/EZOS      # #8 (この直下に app/ が入る)
USER_=debian                  # #9

STEP 1. 前提コマンド

for c in git gh node npm jq tmux curl; do
  printf '%-6s ' "$c"; command -v "$c" || echo 'MISSING'
done
node -v   # v20 以上を推奨
  • 不足があれば: sudo apt-get update && sudo apt-get install -y jq tmux curl
  • Node が古い/無い場合は Node 20 系を導入。
  • gh auth status で GitHub 認証を確認（未認証なら gh auth login）。
  • Claude Code をグローバル導入し、Pro/Max アカウントで認証しておく（~/.claude/.credentials.json）。

STEP 2. インフラ確認（Caddy / リバースプロキシ）

TLS 終端＆リバースプロキシを「まず存在確認 → 有れば利用、無ければ方針提示」の順で決めます。

command -v docker && docker ps --format '{{.Names}}' | grep -i caddy   # saas-caddy 等
ls -d /home/debian/saas/caddy/sites 2>/dev/null                        # サイト定義ディレクトリ
  • Docker の Caddy が動いている場合: sites/*.caddy を 1 枚足すだけで公開できる → STEP 6 へ。
  • Caddy が無い / 別のプロキシの場合: 既存 nginx 等があればその流儀で <host> を 127.0.0.1:<port> へ転送し TLS を張る。プロキシ自体が無ければ導入方針を作業者と合意してから進む（勝手に 443 を専有しない）。

STEP 3. リポジトリ取得

gh repo clone hezoe/EZOS "$APPDIR"    # または: git clone https://github.com/hezoe/EZOS.git "$APPDIR"
cd "$APPDIR/app"

STEP 4. 依存インストール & 初期設定（config.json 生成）

setup.js は環境変数で値を受け取ります（ORIGIN・RPID・PORT を必ず渡す）。data/config.json は .gitignore 対象＝インストールごとの実行時設定です。

cd "$APPDIR/app"
npm install --omit=dev

EZOS_ORIGIN="$ORIGIN" EZOS_RPID="$RPID" EZOS_PORT="$PORT" \
  node setup.js
# => data/config.json を作成する
パスキーの登録は、セキュリティのため常時は受け付けません。初回登録するときだけサーバー上で node bin/open-register.js を実行し、表示されるワンタイム登録キーで登録します（15 分だけ解錠、登録成功で自動失効）。ログイン済み端末からは解錠なしで設定 → パスキー端末管理から追加できます。

STEP 5. systemd 常駐化（自動起動・自動再起動）

KillMode=process は node だけ止めて、node-pty が起こした tmux（永続ターミナル）を再起動で生かし続けるためです。Docker の Caddy から host.docker.internal 経由で届くよう、EZOS は docker0(172.17.0.1) にも待受するため After=docker.service を付けます。

sudo tee /etc/systemd/system/${SERVICE}.service >/dev/null <<UNIT
[Unit]
Description=EZOS (${HOST}) - Claude web cockpit
After=network-online.target docker.service
Wants=network-online.target docker.service

[Service]
Type=simple
User=${USER_}
WorkingDirectory=${APPDIR}/app
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=3
KillMode=process
Environment=NODE_ENV=production
Environment=HOME=/home/${USER_}

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable --now ${SERVICE}
systemctl is-active ${SERVICE}          # => active
ss -tlnp | grep ":${PORT}"              # => 127.0.0.1:<port> で node が待受

STEP 6. Caddy サイト定義（公開）

cat > /home/${USER_}/saas/caddy/sites/${SERVICE}.caddy <<CADDY
${HOST} {
  header {
    Strict-Transport-Security "max-age=31536000; includeSubDomains"
    X-Content-Type-Options "nosniff"
    X-Frame-Options "DENY"
    Referrer-Policy "strict-origin-when-cross-origin"
    Permissions-Policy "geolocation=(), microphone=(self), camera=()"
    -Server
  }
  encode zstd gzip
  reverse_proxy host.docker.internal:${PORT} {
    flush_interval -1
  }
}
CADDY

docker exec saas-caddy caddy validate --config /etc/caddy/Caddyfile
docker exec saas-caddy caddy reload   --config /etc/caddy/Caddyfile
  • flush_interval -1 は SSE/ストリーミング（Claude 出力）をバッファせず流すため。
  • Permissions-Policy の microphone=(self) は音声入力（Web Speech API）のため。
  • reload 後、Caddy が ${HOST} の Let's Encrypt 証明書を自動取得します（#4 の DNS が #1 の IP へ解決していることが前提）。

STEP 7. セッション追跡フック（任意・推奨）

Claude のセッション状態（確認待ち／作業中など）を追跡したい場合、~/.claude/settings.json の各フックで ${APPDIR}/app/bin/ez-hook.sh <state> を呼びます。送信先ポートはスクリプトが data/config.json から自動取得します（localhost 限定・認証不要）。

STEP 8. 検証と初回パスキー登録

getent hosts "$HOST"                                                   # => <IP> $HOST
curl -sS -o /dev/null -w "%{http_code} ssl=%{ssl_verify_result}\n" "$ORIGIN/"   # => 200 ssl=0

200 ssl=0 なら公開成功です。続いて初回パスキーを登録します。

  1. サーバー上で cd "$APPDIR/app" && node bin/open-register.js を実行（15 分の登録解錠 + ワンタイムキー表示）。
  2. STEP 0 #5 で決めた端末のブラウザで ${ORIGIN} を開く。
  3. ログイン画面の「新しい端末のパスキーを追加登録する」に、表示されたワンタイムキーと端末名を入力して登録。
