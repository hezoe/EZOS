1. למה אתם צריכים את EZOS

EZOS נולד מתוך רצון פשוט: לבנות סביבה שמנצלת באמת את מלוא הפוטנציאל של Claude Code. הוא קיים כדי לפרוץ כמה חומות שאי אפשר לעבור פשוט על ידי הרצת claude בטרמינל רגיל.

1. הרצת כמה מופעי Claude במקביל בלי להיתקע

כשאתם מפעילים את Claude על פני כמה פרויקטים במקביל, ייתכן שאחד התהליכים יתקע בשקט בהמתנה לאישור (החלטה ממתינה) — ושואל "האם מותר לבצע את הפעולה הזו?" — ואם לא תשימו לב, כל תהליך העבודה נעצר. EZOS מתריע לכם מיד על בקשת אישור מכל תהליך Claude, ומאפשר לכם להגיב בלחיצה אחת, כך שהחלטה ממתינה לעולם לא תשאיר אתכם תקועים. בנוסף, מתנגן צליל התראה (כגון צליל שבירת המגבלה) כשמשהו ממתין לאישור.

2. רץ על השרת / בדקו זאת מהנייד, גם כשאתם בדרכים

מכיוון שהוא מבוסס דפדפן, כל התהליכים רצים על ה-VPS (השרת). סגרו את המחשב המקומי, והעבודה ממשיכה. ואתם יכולים לבדוק את הסטטוס ולענות על בקשות אישור מהנייד בזמן שאתם בחוץ. מכיוון ש-tmux שומר על ההפעלות חיות, אתם יכולים להמשיך עבודה שהתחלתם על המחשב בדיוק מהמקום שבו הפסקתם, על אותו המסך בנייד.

3. חלונית קלט שמתקנת את אי-ההתאמה בין ה-IME לקונסולה המרוחקת

בעת הקלדה בשפות שמשתמשות ב-IME (כגון יפנית), חיבור איטי גורם להמרת ה-IME ולקונסולה המרוחקת לצאת מסנכרון, מה שהופך את הקלט למתסכל להחריד. EZOS מעניק לכל טרמינל חלונית קלט ייעודית כך שתוכלו להרכיב טקסט מקומית ולשלוח רק את התווים הסופיים בבת אחת, מה שמקל על כאב הקלט הזה (מתג הקלט).

4. EZbrowser, שנוסף כדי להזיז קבצים

בנוסף לEZeditor לעריכת קבצים, הוספנו את EZbrowser (מנהל קבצים מובנה) כדי להזיז קבצים — העלאה, הורדה, העתקה, מחיקה וכן הלאה. הוא מאפשר לכם לעבוד עם קבצי השרת כולם בתוך הדפדפן.

2. דוגמה מהעולם האמיתי: אירוח אתר בדומיין אחר על אותו שרת, שנבנה על ידי AI

העוצמה האמיתית של EZOS אינה רק בשיחה עם Claude. היא מתגלה במיטבה בתבנית כמו זו: על אותו VPS, לבנות ולתפעל אתר אינטרנט נפרד לחלוטין בדומיין אחר בעזרת AI (Claude Code), ולפרסם אותו דרך אותו פרוקסי הפוך (Caddy).

איך זה עובד: שרת אחד, ו-Caddy מנתב מספר דומיינים

Caddy יכול להחזיק הגדרת אתר לכל דומיין. כל דומיין פשוט מבצע פרוקסי הפוך לאפליקציה שרצה על פורט localhost משלה, כך שכמה אתרים יכולים לחיות זה לצד זה על מכונה אחת.

  • ezos.example.com ← EZOS (תא הטייס הזה)
  • www.takikawa-airplane.jp ← אתר אינטרנט אחר (אפליקציה נפרדת על פורט נפרד)

אתם מריצים את Claude Code מה-EZterminal של EZOS כדי לכתוב את הקוד של אותו אתר אחר, עורכים קבצים ישירות ב-EZbrowser / EZeditor, ובונים ופורסים אותו על אותו השרת. מכיוון שהוא מבוסס דפדפן, אתם יכולים לומר ל-Claude "תקן את החלק הזה באתר" מהנייד, אפילו בזמן נסיעה.

הדוגמה: האתר התאגידי של Takikawa-Airplane

דוגמה אמיתית מצוינת היא www.takikawa-airplane.jp (Takikawa Sky Park / Takikawa Airplane). האתר הזה רץ על אותו השרת כמו EZOS, נבנה ומתעדכן על ידי Claude Code באמצעות Next.js, ומתפרסם דרך אותו פרוקסי הפוך של Caddy כמו EZOS.

  • Production www.takikawa-airplane.jp ואתר staging www2.takikawa-airplane.jp (מוגן ב-Basic-auth) מתקיימים זה לצד זה כתהליכי Next.js נפרדים על פורטים נפרדים.
  • סקירה על ה-staging ← קידום ל-production אם זה נראה טוב — כל התהליך הזה מונע על ידי Claude Code בתוך EZOS.
  • תמיכה דו-לשונית (JA/EN), אופטימיזציה לנייד, וקליטת מאמרי טור — כולם משתפרים ברציפות בגישת AI-first.
בקצרה, EZOS הוא גם "תא טייס להפקת המרב מ-Claude" וגם בסיס בית לגידול אתר production אמיתי ונפרד בתוך אותה קופסה בעזרת אותו Claude עצמו. VPS אחד הופך בבת אחת לסביבת הפיתוח שלכם, לסדנה של ה-AI שלכם, ולשרת הציבורי של מספר דומיינים.

3. ארכיטקטורת המערכת

כל התקנה מורכבת מאפליקציית Node אחת + שירות systemd + הגדרת אתר של Caddy. הדפדפן מתחבר דרך Caddy (סיום TLS ופרוקסי הפוך) אל אפליקציית Node שמאזינה על localhost.

רכיבתפקיד
דפדפן (מחשב / נייד)מסך EZOS. מציג את הטרמינל באמצעות xterm.js ומתקשר דו-כיוונית עם השרת מעל WebSocket.
Caddyמאזין על הדומיין הציבורי שלכם (למשל ezos.example.com), משיג אוטומטית תעודת TLS, ומבצע פרוקסי הפוך אל אפליקציית Node על localhost.
אפליקציית EZOS Nodeserver.js. שרת ה-HTTP/WebSocket, אימות passkey, אספקת ה-UI, ו-API הקבצים. מאזין על 127.0.0.1 (למשל פורט 3101).
node-pty + tmuxמגשר בין WebSocket לפסאודו-טרמינל (pty). כל טאב מתחבר להפעלת tmux ez_<sid>, כך שאותו מסך ממשיך גם לאחר ניתוק או החלפת מכשירים.
claude CLIClaude Code עצמו, שרץ באופן אינטראקטיבי בתוך tmux. דורש חשבון Pro/Max לצורך אימות.
hook ← /api/beathook של Claude Code קורא ל-ez-hook.sh כדי לדווח על מצב ההפעלה (המתנה לאישור, בעבודה וכו') לשרת.
app/data/*.jsonנתוני זמן ריצה כגון passkeys, טוקנים והגדרות (ללא מסד נתונים; מוחרג באמצעות .gitignore).

4. התחברות ו-passkeys

EZOS מבצע אימות באמצעות passkeys של WebAuthn (שניתן לאחסן בכלים כמו 1Password).

  • התחברות: לחצו על "🔑 התחבר עם passkey" והציגו את ה-passkey שלכם באמצעות המדדים הביומטריים של המכשיר או דומיהם.
  • הגדרה ראשונית: רשמו את ה-passkey הראשון שלכם לאחר פתיחת חלון הרישום על השרת.
  • הוספת מכשיר חדש: ממכשיר שכבר מחובר, אתם יכולים להוסיף אחד ישירות דרך הגדרות ← ניהול מכשירי passkey. אם אין לכם כלל מכשיר שיכול להתחבר, הריצו node bin/open-register.js על השרת כדי לפתוח את הרישום ל-15 דקות בלבד (break-glass).
מטעמי אבטחה, רישום passkey חדש ממצב לא מאומת אינו מתקבל כברירת מחדל. במקרה של נעילה בחוץ (אובדן כל המכשירים שלכם), רק מי שיכול להתחבר ב-SSH לשרת יכול לפתוח זמנית את הרישום.

7. EZterminal (טרמינל)

הדפדפן שלכם הופך לטרמינל של ה-VPS עצמו, ומאפשר לכם להריץ את claude באופן אינטראקטיבי. בנוי מ-xterm.js + WebSocket + node-pty + tmux, ההפעלות שורדות גם לאחר ניתוק, ואתם יכולים להתחבר לאותה הפעלה ממחשב או מנייד.

שדה קלט ומתג קלט

לכל טרמינל יש שדה קלט ייעודי, עם מתג "קלט" בפינה הימנית העליונה שלו.

  • ON (עריכה בשדה הקלט): אתם עורכים בשדה הקלט המקומי ושולחים לאחר שסיימתם את הטקסט. קלט ישיר לטרמינל נעול, כך שה-IME נשאר יציב. הקלט שלכם לא ייצא מסנכרון גם בחיבור איטי.
  • OFF (קלט ישיר): אתם מקלידים מקשים ישירות לתוך הטרמינל.
  • בשדה הקלט, Enter = שורה חדשה / Ctrl+Enter = שליחה. אתם יכולים גם לשלוח בעזרת כפתור Send ⏎.

שורת מקשי הבקרה וכפתורים שונים

כפתורתיאור
⏎Tab↑↓←→^C^DEsc ועודשורת מקשים ששולחת מקשי בקרה לטרמינל.
G↓ / G↑פעולות git. G↓ = משיכה מ-GitHub, G↑ = commit ו-push.
🎤 מיקרופוןקלט קולי. מכניס את הטקסט המזוהה לשדה הקלט (כאשר ON) או לטרמינל (כאשר OFF).
📎 צירוףמעלה קובץ כגון תמונה לתיקייה הנוכחית ומכניס את הנתיב שלו לשדה הקלט. גם גרירה-ושחרור או הדבקה עובדים.
⇧ / ⇩מעבר לרשומה הקודמת / הבאה בהיסטוריית הקלט.

לחיצה על נתיבי קבצים והעתקת בחירות

  • כאשר נתיב קובץ מופיע בטרמינל או בפלט של Claude, לחיצה עליו פותחת אותו ישירות ב-EZeditor (עובד בין אם מתג הקלט הוא ON ובין אם OFF).
  • בחירת טקסט עם העכבר מעתיקה אותו. כשאתם רוצים לדווח על פעולות עכבר לאפליקציה במקום זאת, החזיקו את Alt תוך כדי הפעולה.

גלילת המסך (קריאת היסטוריה קודמת)

  • גררו או לחצו על פס הגלילה בקצה הימני של הקונסולה כדי לחזור אל ההיסטוריה הקודמת. מיקום הידית מציין היכן אתם נמצאים בגלילה לאחור.
  • אפשר לגלול גם עם גלגלת העכבר או משטח המגע (כוונן כך שהתאוצה לא חזקה מדי).
  • הקישו Shift+↑ / Shift+↓ כדי לגלול צעד אחד בכל פעם (לחצו קודם על הקונסולה כדי שתהיה בפוקוס). נוח לקריאה חוזרת איטית בלי לאבד את המקום. ↑↓ רגילים משמשים להיסטוריית ה-shell / בחירה ב-Claude, ולכן הגלילה נעשית עם Shift לחוץ.
  • כאשר אפליקציה במסך מלא כמו Claude Code פועלת, זה גולל את התצוגה של האפליקציה עצמה. ב-shell רגיל זה חוזר דרך ההיסטוריה (scrollback) של הטרמינל.

חיבור והתחברות מחדש

  • גם אם החיבור נופל, הוא מתחבר מחדש אוטומטית (מתאושש אפילו ב-Wi-Fi בטיסה וכדומה).
  • אם תפתחו את אותו טאב על מכשיר אחר, התצוגה עוברת לשם. במכשיר המקורי, תוכלו להתאושש בלחיצה על כפתור ההתחברות מחדש, על Enter, או בהקשה על הטאב.

8. EZbrowser (ניהול קבצים)

9. EZeditor (עורך)

ערכו קבצי טקסט על השרת מתוך הדפדפן שלכם. נפתח מנתיב קובץ ב-EZbrowser או בטרמינל.

  • תפריט קובץ: שמירה (מקביל ל-Ctrl+S), שמירה בשם.
  • תפריט עריכה: גזירה / העתקה / הדבקה.
  • אתם יכולים לפתוח מספר קבצים כטאבים. אם תנסו לסגור עם שינויים שלא נשמרו, תתבקשו לאשר.
  • כולל הדגשת תחביר בסיסית.

11. סקירת התקנה

EZOS פתוח בקוד פתוח ב-GitHub, כך שכל אחד יכול להתקין אותו בסביבה שלו. github.com/hezoe/EZOS

התהליך הכללי הוא כדלקמן.

git clone https://github.com/hezoe/EZOS.git
cd EZOS/app
npm install --omit=dev
node setup.js          # יוצר את config.json (rpID / origin / port וכו')
node server.js         # הפעלה (בדרך כלל רץ כשירות systemd)

לצורך סיום TLS ופרוקסי הפוך בדומיין ציבורי, השתמשו ב-Caddy כדי לחבר שם מארח ציבורי כמו ezos.example.com אל הפורט המאזין על localhost.

להוראות התקנה מפורטות, ראו את מדריך ההתקנה הנפרד (המכסה כיצד להחליט על ה-IP שלכם, שם המארח הציבורי, DNS, מכשיר רישום ה-passkey, פורט/שם שירות, וכן הגדרת Caddy, הרצה תחת systemd, והגדרת ה-hook).
