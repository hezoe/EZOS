EZOS User Manual

EZOS is your own personal cockpit for getting the most out of Claude Code from a browser. With passkey authentication, you can run claude interactively on your VPS from any device's browser — whether on a PC or a phone.

1. Why you need EZOS

EZOS was born from a simple desire: to build an environment for really getting the most out of Claude Code. It exists to break through several walls that you can't get past by just running claude in an ordinary terminal.

1. Keep several Claudes running in parallel without stalling

When you launch Claude across several projects in parallel, one process may quietly be stuck waiting for confirmation (a pending decision) — asking "Is it OK to run this operation?" — and if you don't notice, the whole workflow grinds to a halt. EZOS alerts you instantly to a confirmation request from any Claude process and lets you respond with a single click, so a pending decision never leaves you stuck. A notification sound (such as the limit-break chime) also plays when something is waiting for confirmation.

2. Runs on the server / check it from your phone, even on the go

Because it's browser-based, every process runs on the VPS (server). Close your local PC and the work keeps going. And you can check status and answer confirmation prompts from your phone while you're out and about. Since tmux keeps sessions alive, you can pick up work you started on your PC right where you left off, on the same screen on your phone.

3. An input pane that fixes the mismatch between your IME and the remote console

When typing in languages that use an IME (such as Japanese), a slow connection means the IME's conversion and the remote console fall out of sync, making input incredibly frustrating. EZOS gives each terminal a dedicated input pane so you can compose text locally and send only the finalized characters in one go, easing that input pain (the input toggle switch).

4. EZbrowser, added for moving files around

On top of EZeditor for editing files, we added EZbrowser (a built-in file manager) for moving files around — uploading, downloading, copying, deleting, and so on. It lets you work with the server's files entirely within the browser.

2. Real-world example: hosting a site on another domain on the same server, built by AI

The real power of EZOS isn't just talking to Claude. It shows best in a pattern like this: on the same VPS, build and operate a completely separate website on a different domain with AI (Claude Code), and publish it through the same reverse proxy (Caddy).

How it works: one server, and Caddy routes multiple domains

Caddy can hold a site definition per domain. Each domain simply reverse-proxies to an app running on its own localhost port, so several sites can live side by side on a single machine.

  • ezos.example.com → EZOS (this cockpit)
  • www.takikawa-airplane.jp → another website (a separate app on a separate port)

You run Claude Code from EZOS's EZterminal to write that other site's code, edit files directly in EZbrowser / EZeditor, and build and deploy it on the same server. Because it's browser-based, you can tell Claude "fix this part of the site" from your phone, even while traveling.

The example: the Takikawa-Airplane corporate site

A great real example is www.takikawa-airplane.jp (Takikawa Sky Park / Takikawa Airplane). This site runs on the same server as EZOS, is built and updated by Claude Code using Next.js, and is published through the same Caddy reverse proxy as EZOS.

  • Production www.takikawa-airplane.jp and a staging site www2.takikawa-airplane.jp (Basic-auth protected) coexist as separate Next.js processes on separate ports.
  • Review on staging → promote to production if it looks good — that whole flow is driven with Claude Code inside EZOS.
  • Bilingual (JA/EN) support, mobile optimization, and ingesting column articles are all continuously improved AI-first.
In short, EZOS is both "a cockpit for getting the most out of Claude" and a home base for growing a separate, real production site inside the same box using that very Claude. One VPS becomes your dev environment, your AI's workshop, and the public server for multiple domains all at once.

3. System architecture

Each installation is made up of one Node app + a systemd service + a Caddy site definition. The browser connects through Caddy (TLS termination and reverse proxy) to the Node app listening on localhost.

ComponentRole
Browser (PC / phone)The EZOS screen. Renders the terminal with xterm.js and communicates bidirectionally with the server over WebSocket.
CaddyListens on your public domain (e.g. ezos.example.com), automatically obtains a TLS certificate, and reverse-proxies to the Node app on localhost.
EZOS Node appserver.js. The HTTP/WebSocket server, passkey authentication, UI delivery, and file API. Listens on 127.0.0.1 (e.g. port 3101).
node-pty + tmuxBridges WebSocket and a pseudo-terminal (pty). Each tab attaches to the tmux session ez_<sid>, so the same screen continues even after disconnecting or switching devices.
claude CLIClaude Code itself, run interactively inside tmux. Requires a Pro/Max account for authentication.
hook → /api/beatA Claude Code hook calls ez-hook.sh to report session state (waiting for confirmation, working, etc.) to the server.
app/data/*.jsonRuntime data such as passkeys, tokens, and settings (no database; excluded via .gitignore).

4. Login and passkeys

EZOS authenticates with WebAuthn passkeys (which can be stored in tools like 1Password).

  • Login: Press "🔑 Log in with a passkey" and present your passkey using your device's biometrics or similar.
  • First-time setup: Register your first passkey after opening the registration window on the server.
  • Adding a new device: From a device that's already logged in, you can add one directly via Settings → Passkey device management. If you have no device that can log in at all, run node bin/open-register.js on the server to unlock registration for just 15 minutes (break-glass).
For security, new passkey registration from an unauthenticated state is not accepted by default. In case you get locked out (losing all your devices), only someone who can SSH into the server can temporarily unlock registration.

7. EZterminal (terminal)

Your browser becomes the VPS's terminal itself, letting you run claude interactively. Built from xterm.js + WebSocket + node-pty + tmux, sessions persist even after disconnecting, and you can connect to the same session from a PC or phone.

Input field and input toggle switch

Each terminal has a dedicated input field, with an "Input" switch at its top right.

  • ON (edit in the input field): You edit in the local input field and send once you've finalized the text. Direct input to the terminal is locked, so the IME stays stable. Your input won't fall out of sync even on a slow connection.
  • OFF (direct input): You type keys directly into the terminal.
  • In the input field, Enter = newline / Ctrl+Enter = send. You can also send with the Send ⏎ button.

Control-key row and various buttons

ButtonDescription
⏎Tab↑↓←→^C^DEsc and moreA key row that sends control keys to the terminal.
GitHub ↓ / ↑Git operations. The buttons show the GitHub (Octocat) icon. ↓ = pull from GitHub, ↑ = commit and push.
🎤 MicrophoneVoice input. Puts the recognized text into the input field (when ON) or the terminal (when OFF).
📎 AttachUploads a file such as an image to the current directory and inserts its path into the input field. Drag-and-drop or paste also works.
⇧ / ⇩Move to the previous / next entry in the input history.

Clicking file paths and copying selections

  • When a file path appears in the terminal or Claude's output, clicking it opens it directly in EZeditor (works whether the input toggle is ON or OFF).
  • Selecting text with the mouse copies it. When you want to report mouse actions to the app instead, hold Alt while operating.
  • On iPhone and the like (where touching the console directly doesn't bring up a selection popup), long-press the console or press the 📋 button in the key row to open the screen's text in a selectable view. There, long-press to select a range and copy, or use "Copy all" at the top right to copy everything.

Scrolling the screen (reading past history)

  • Drag or click the scrollbar on the right edge of the console to go back through past history. The thumb position shows where you are in the scrollback.
  • You can also scroll with the mouse wheel or touchpad (tuned so the momentum isn't too strong).
  • Press Shift+↑ / Shift+↓ to scroll one step at a time (click the console first so it has focus). Handy for reading back slowly without losing your place. Plain ↑↓ are used for shell history / Claude's selection, so scrolling is done with Shift held.
  • While a full-screen app such as Claude Code is running, this scrolls that app's own view. At a plain shell it goes back through the terminal's scrollback (history).

Connection and reconnection

  • Even if the connection drops, it reconnects automatically (recovering even on in-flight Wi-Fi and the like).
  • If you open the same tab on another device, the display moves there. On the original device, you can recover by pressing the reconnect button, Enter, or tapping the tab.

9. EZeditor (editor)

Edit text files on the server from within your browser. Opened from a file path in EZbrowser or the terminal.

  • File menu: Save (equivalent to Ctrl+S), Save As.
  • Edit menu: Cut / copy / paste.
  • You can open multiple files as tabs. If you try to close with unsaved changes, you'll be prompted to confirm.
  • Includes basic syntax highlighting.

11. Installation overview

EZOS is open-sourced on GitHub, so anyone can set it up in their own environment. github.com/hezoe/EZOS

The rough flow is as follows.

git clone https://github.com/hezoe/EZOS.git
cd EZOS/app
npm install --omit=dev
node setup.js          # generates config.json (rpID / origin / port, etc.)
node server.js         # start it (normally runs as a systemd service)

For TLS termination and reverse proxying on a public domain, use Caddy to connect a public hostname like ezos.example.com to the listening port on localhost.

For detailed setup instructions, see the separate installation manual (covering how to decide on your IP, public hostname, DNS, passkey registration device, port/service name, plus Caddy configuration, running under systemd, and hook setup).
