EZOS 取扱説明書

EZOS は、ブラウザから Claude Code を使い込むための自分専用コックピットです。パスキー認証付きで、PC でもスマホでも、どの端末のブラウザからでも VPS 上の claude を対話実行できます。

1. なぜ EZOS が必要なのか

EZOS は「Claude Code を徹底的に使い込むための環境」を提供したい、という動機から生まれました。ふつうにターミナルで claude を叩くだけでは越えられない、いくつかの壁を解消するために作られています。

① 並列で走る複数の Claude を、止めずに回す

複数のプロジェクトで Claude を並列に起動すると、あるプロセスが「この操作を実行してよいですか？」と確認待ち（判断留め）で止まっていることに気づけず、そこで仕事全体が停滞してしまいます。EZOS は、別プロセスの Claude からの確認を即座に知らせ、ワンクリックで応答できるようにすることで、判断留めで手が止まらないようにしました。確認待ちには通知音（リミットブレイク音など）も鳴ります。

② サーバー上で動く／スマホから移動中でも確認できる

ブラウザ表示型にしたことで、プロセスはすべて VPS（サーバー）上で動作します。ローカル PC を閉じても処理は止まりません。そしてスマホなどからも、移動中に状況を確認し、確認待ちに応答できます。tmux でセッションが永続するため、PC で始めた作業の続きをスマホの同じ画面で見られます。

③ 入力画面で、IME とリモートコンソールのズレを解消

多言語（日本語など IME を使う言語）で入力する場合、通信が遅いとIME の変換動作とリモートコンソールの同期が取れず、入力が非常にストレスでした。EZOS は各ターミナルに専用の入力画面を用意し、手元で確定した文字だけをまとめて送れるようにして、この入力ストレスを改善しています（入力切替スイッチ）。

④ ファイルのやり取りのために EZbrowser を追加

ファイルを編集する EZeditor に加えて、ファイルのやり取り（アップロード／ダウンロード／コピー／削除など）のために EZbrowser（内蔵ファイルマネージャ）を追加しました。ブラウザ上で完結してサーバーのファイルを扱えます。

2. 活用例：リバースプロキシで「別ドメインのサイト」を同じサーバに同居させ、AIで構築する

EZOS の真価は、単に Claude と対話できることだけではありません。同じ VPS 上に、まったく別のドメインの Web サイトを AI（Claude Code）で構築・運用し、同じリバースプロキシ（Caddy）で公開する——という使い方に、その力がよく表れます。

仕組み：1 台のサーバー + Caddy が複数ドメインを振り分ける

Caddy はドメインごとのサイト定義を持てます。各ドメインを、localhost の別ポートで動くアプリへリバースプロキシするだけで、同じ 1 台の上に複数のサイトを同居できます。

  • ezos.example.com → EZOS（このコックピット）
  • www.takikawa-airplane.jp → もう一つの Web サイト（別アプリ・別ポート）

あなたは EZOS の EZterminal から Claude Code を動かして、その別サイトのコードを書き、EZbrowser／EZeditor でファイルを直接いじり、同じサーバー上でビルド・デプロイします。ブラウザ型なので、スマホから移動中でも「サイトのここを直して」と Claude に指示できます。

実例：Takikawa-Airplane のコーポレートサイト

この良い実例が www.takikawa-airplane.jp（滝川スカイパーク / Takikawa Airplane）です。このサイトは、EZOS が動いているのと同じサーバー上で、Next.js を用いて Claude Code によって構築・更新され、EZOS と同じ Caddy のリバースプロキシから公開されています。

  • 本番 www.takikawa-airplane.jp と、控え（ステージング） www2.takikawa-airplane.jp（Basic 認証つき）を、それぞれ別ポートの Next.js プロセスとして同居。
  • 控えで内容を確認 → 問題なければ本番へ昇格、というフローも、すべて EZOS 上の Claude Code で回せます。
  • 多言語（日英）対応やスマホ最適化、コラム記事の取り込みなども AI 主導で継続的に改善しています。
要するに EZOS は「Claude を使い込むためのコックピット」であると同時に、その Claude を使って“別の実運用サイト”を同じ箱の中で育てるための拠点にもなります。1 台の VPS が、開発環境であり、AI の作業場であり、複数ドメインの公開サーバーでもある——という形です。

3. システム構成図

各インストールは 1 つの Node アプリ + systemd サービス + Caddy のサイト定義 で成り立ちます。ブラウザは Caddy（TLS 終端・リバースプロキシ）を経由して、localhost で待ち受ける Node アプリに繋がります。

要素役割
ブラウザ（PC / スマホ）EZOS の画面。xterm.js でターミナルを描画し、WebSocket でサーバーと双方向通信。
Caddy公開ドメイン（例 ezos.example.com）で待ち受け、TLS 証明書を自動取得し、localhost の Node アプリへリバースプロキシ。
EZOS Node アプリserver.js。HTTP/WebSocket サーバー、パスキー認証、UI 配信、ファイル API。127.0.0.1 で待受（例: ポート 3101）。
node-pty + tmuxWebSocket と擬似端末（pty）を橋渡し。各タブは tmux セッション ez_<sid> に attach するため、切断・別端末でも同じ画面が続く。
claude CLItmux 内で対話実行される Claude Code 本体。Pro/Max アカウント認証が前提。
フック → /api/beatClaude Code のフックが ez-hook.sh を叩き、セッション状態（確認待ち／作業中など）をサーバーへ通知。
app/data/*.jsonパスキー・トークン・設定などの実行時データ（DB 不使用、.gitignore 対象）。

4. ログインとパスキー

EZOS は WebAuthn パスキーで認証します（1Password などに保存可）。

  • ログイン: 「🔑 パスキーでログイン」を押し、端末の生体認証などでパスキーを提示します。
  • 初回セットアップ: 最初のパスキーは、サーバーで登録ウィンドウを開いてから登録します。
  • 新しい端末の追加: すでにログイン済みの端末からは、設定 → パスキー端末管理でそのまま追加できます。ログインできる端末が一つも無い場合は、サーバー上で node bin/open-register.js を実行して 15 分だけ登録を解錠します（break-glass）。
セキュリティのため、未認証からの新規パスキー登録は常時は受け付けません。締め出し（全端末喪失）に備え、SSH でサーバーに入れる人だけが登録を一時解錠できる仕組みです。

7. EZterminal（ターミナル）

ブラウザが VPS のターミナルそのものになり、claude を対話実行できます。xterm.js + WebSocket + node-pty + tmux で構成され、切断してもセッションは永続、PC/スマホから同一セッションに接続できます。

入力欄と入力切替スイッチ

各ターミナルには専用の入力欄と、その右上に「入力」スイッチがあります。

  • ON（入力欄で編集）: 手元の入力欄で編集し、確定してから送信します。ターミナルへの直接入力はロックされ、IME が安定します。通信が遅い環境でも入力がズレません。
  • OFF（直接入力）: ターミナルに直接キー入力します。
  • 入力欄では Enter＝改行 / Ctrl+Enter＝送信。送信 ⏎ ボタンでも送れます。

制御キー行・各種ボタン

ボタン説明
⏎Tab↑↓←→^C^DEsc ほかターミナルへ制御キーを送るキー行。
Claude 起動ボタン（Claude アイコン）⏎ と Tab の間にあるボタン。クリックすると claude と Enter を送信して Claude を起動します。
GitHub ↓ / ↑Git 操作。GitHub の Octocat アイコン付きのボタンです。↓=GitHub から pull、↑=コミットして push。
🎤 マイク音声入力。認識結果を入力欄（ON 時）またはターミナル（OFF 時）へ入れます。
📎 添付画像などのファイルをカレントディレクトリへアップロードし、パスを入力欄へ挿入。ドラッグ＆ドロップや貼り付けでも可。
⇧ / ⇩入力履歴を前／次へ。

ファイルパスのクリックと選択コピー

  • ターミナルや Claude の出力中に現れたファイルパスをクリックすると、EZeditor で直接開きます（入力切替 ON/OFF どちらでも動作）。
  • テキストをマウスで選択するとコピーされます。アプリ側へマウス操作を報告したいときは Alt＋操作。
  • iPhone など（コンソールを直接タッチしても選択ポップアップが出ない環境）では、コンソールを長押しするか、キー行の 📋 ボタンを押すと、画面のテキストを選択可能な画面で開きます。そこで長押しして範囲を選択→コピー、または右上の「すべてコピー」で全文をコピーできます。

画面のスクロール（過去履歴を読む）

  • コンソール画面の右端のスクロールバーをドラッグ／クリックすると、過去の履歴へ遡れます。つまみの位置が現在のスクロール位置を表します。
  • マウスホイール／タッチパッドでもスクロールできます（勢いが強すぎないよう調整済み）。
  • Shift＋↑ / Shift＋↓ で1 段ずつスクロールします（コンソールをクリックしてフォーカスがある状態で有効）。行を見失わずゆっくり読み返すのに便利です。素の ↑↓ はシェル履歴／Claude の選択移動に使うため、スクロールは Shift と併用します。
  • Claude Code など全画面アプリの実行中は、そのアプリ自身の表示をスクロールします。素のシェルでは端末のスクロールバック（履歴）を遡ります。

接続と再接続

  • 接続が切れても自動的に再接続します（機内 Wi-Fi 等でも復帰）。
  • 別のデバイスで同じタブを開くと、そちらへ表示が移ります。元の端末では再接続ボタン／Enter／タブのタップで復帰できます。

9. EZeditor（エディタ）

サーバー上のテキストファイルをブラウザ内で編集します。EZbrowser やターミナルのファイルパスから開かれます。

  • ファイルメニュー: 保存（Ctrl+S 相当）・別名で保存。
  • 編集メニュー: カット / コピー / ペースト。
  • 複数ファイルをタブで開けます。未保存のまま閉じようとすると確認が出ます。
  • 簡易シンタックスハイライト付き。

11. インストール概要

EZOS は GitHub で公開されており、誰でも自分の環境に構築できます。github.com/hezoe/EZOS

大まかな流れは次の通りです。

git clone https://github.com/hezoe/EZOS.git
cd EZOS/app
npm install --omit=dev
node setup.js          # config.json を生成（rpID / origin / port など）
node server.js         # 起動（通常は systemd サービスとして常駐）

公開ドメインでの TLS 終端・リバースプロキシには Caddy を使い、ezos.example.com のような公開ホスト名を localhost の待受ポートへ繋ぎます。

詳しい導入手順は別冊のインストールマニュアルを参照してください（IP・公開ホスト名・DNS・パスキー登録端末・ポート/サービス名の決め方、Caddy 設定、systemd 常駐、フック設定まで）。
