EZOS מדריך התקנה

זהו מדריך שלב-אחר-שלב לפריסת EZOS על שרת חדש (VPS) ולהנגשתו בדומיין ציבורי. כל אחד יכול לבנות סביבה משלו ישירות מ-GitHub.

מדריך זה נכתב מתוך הנחה שClaude Code יבצע את העבודה. המפעיל פשוט מתחבר לשרת דרך SSH, מתקין ומאמת את Claude Code, ואז מנחה אותו: "התקן את המאגר הזה (github.com/hezoe/EZOS)." לאחר מכן Claude קורא את המסמך הזה ומבצע את ההתקנה באופן אינטראקטיבי. אם אתם מעדיפים לבצע זאת ידנית, אותם השלבים חלים.

סקירת ארכיטקטורה

כל התקנה מורכבת מאפליקציית Node יחידה + שירות systemd + הגדרת אתר של Caddy.

הדפדפן מתחבר דרך Caddy (סיום TLS ופרוקסי הפוך) אל אפליקציית Node המאזינה ב-localhost. הטרמינל מגושר לפסאודו-טרמינל באמצעות node-pty ‏+ tmux, ובתוכו claude רץ באופן אינטראקטיבי.

דרישות מערכת

‏EZOS מורכב מאפליקציית Node הפועלת באופן מתמשך בשרת (מארח) ומהלקוח (דפדפן) המתחבר אליה. לפני ההתקנה, ודאו שהסביבה שלכם עומדת בתנאים שלהלן.

שלב 0. החלטות שיש לקבל מראש

אלו ערכים התלויים בסביבה שלכם ולא ניתן להחליט עליהם אוטומטית. אין להמשיך עד שכולם מולאו (‏#3 ו-#6–#9 ניתן להשאיר בברירת המחדל).

שלב 2. בדיקת תשתית (Caddy / פרוקסי הפוך)

החליטו על סיום TLS ופרוקסי הפוך בסדר הבא: "תחילה בדקו אם קיים אחד ← השתמשו בו אם כן, אחרת הציעו גישה."

command -v docker && docker ps --format '{{.Names}}' | grep -i caddy   # e.g. saas-caddy
ls -d /home/debian/saas/caddy/sites 2>/dev/null                        # site-definitions directory
  • אם Caddy מבוסס-Docker פועל: ניתן לפרסם רק על ידי הוספת קובץ sites/*.caddy יחיד ← עברו לשלב 6.
  • אם אין Caddy / קיים פרוקסי אחר: אם קיים nginx (או דומה), פעלו לפי המוסכמות שלו כדי להעביר <host> אל 127.0.0.1:<port> והגדירו TLS. אם אין פרוקסי כלל, סכמו על גישת התקנה עם המפעיל לפני שתמשיכו (אל תתפסו את פורט 443 בעצמכם).

שלב 4. התקנת תלויות והתקנה ראשונית (יצירת config.json)

setup.js לוקח את ערכיו ממשתני סביבה (יש להעביר ORIGIN, ‏RPID ו-PORT). ‏data/config.json מכוסה על ידי .gitignore, כלומר זוהי תצורת ריצה ייחודית לכל התקנה.

cd "$APPDIR/app"
npm install --omit=dev

EZOS_ORIGIN="$ORIGIN" EZOS_RPID="$RPID" EZOS_PORT="$PORT" \
  node setup.js
# => creates data/config.json
מטעמי אבטחה, רישום passkey אינו מתקבל בכל עת. רק עבור הרישום הראשוני, הריצו node bin/open-register.js על השרת ורשמו באמצעות מפתח הרישום החד-פעמי שהיא מציגה (נפתח למשך 15 דקות בלבד; מבוטל אוטומטית עם רישום מוצלח). ממכשיר שכבר מחובר ניתן להוסיף passkeys ללא פתיחת נעילה, דרך הגדרות ← ניהול מכשירי passkey.

שלב 5. הרצה כשירות systemd (הפעלה אוטומטית, הפעלה מחדש אוטומטית)

KillMode=process עוצר רק את node, כך שה-tmux (הטרמינל המתמשך) שנוצר על ידי node-pty נשאר פעיל בין הפעלות מחדש. כדי שבקשות מ-Caddy מבוסס-Docker יגיעו דרך host.docker.internal, ‏EZOS מאזין גם ל-docker0 ‏(172.17.0.1), ולכן נוסף After=docker.service.

sudo tee /etc/systemd/system/${SERVICE}.service >/dev/null <<UNIT
[Unit]
Description=EZOS (${HOST}) - Claude web cockpit
After=network-online.target docker.service
Wants=network-online.target docker.service

[Service]
Type=simple
User=${USER_}
WorkingDirectory=${APPDIR}/app
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=3
KillMode=process
Environment=NODE_ENV=production
Environment=HOME=/home/${USER_}

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable --now ${SERVICE}
systemctl is-active ${SERVICE}          # => active
ss -tlnp | grep ":${PORT}"              # => node listening on 127.0.0.1:<port>

שלב 6. הגדרת אתר של Caddy (פרסום)

cat > /home/${USER_}/saas/caddy/sites/${SERVICE}.caddy <<CADDY
${HOST} {
  header {
    Strict-Transport-Security "max-age=31536000; includeSubDomains"
    X-Content-Type-Options "nosniff"
    X-Frame-Options "DENY"
    Referrer-Policy "strict-origin-when-cross-origin"
    Permissions-Policy "geolocation=(), microphone=(self), camera=()"
    -Server
  }
  encode zstd gzip
  reverse_proxy host.docker.internal:${PORT} {
    flush_interval -1
  }
}
CADDY

docker exec saas-caddy caddy validate --config /etc/caddy/Caddyfile
docker exec saas-caddy caddy reload   --config /etc/caddy/Caddyfile
  • flush_interval -1 מזרים SSE/streaming (פלט של Claude) ללא באפרינג.
  • microphone=(self) ב-Permissions-Policy מיועד לקלט קולי (‏Web Speech API).
  • לאחר ה-reload, ‏Caddy משיג אוטומטית תעודת Let's Encrypt עבור ${HOST} (זה מניח שה-DNS מ-#4 מפנה ל-IP שב-#1).

שלב 7. hooks למעקב אחר הפעלה (אופציונלי, מומלץ)

אם ברצונכם לעקוב אחר מצב ההפעלה של Claude (ממתין לאישור, עובד וכדומה), קראו ל-${APPDIR}/app/bin/ez-hook.sh <state> מכל hook ב-~/.claude/settings.json. הסקריפט משיג את פורט היעד אוטומטית מ-data/config.json (‏localhost בלבד, ללא צורך באימות).

שלב 8. אימות ורישום ה-passkey הראשון

getent hosts "$HOST"                                                   # => <IP> $HOST
curl -sS -o /dev/null -w "%{http_code} ssl=%{ssl_verify_result}\n" "$ORIGIN/"   # => 200 ssl=0

אם קיבלתם 200 ssl=0, הפרסום הצליח. כעת רשמו את ה-passkey הראשון.

  1. על השרת, הריצו cd "$APPDIR/app" && node bin/open-register.js (פתיחת רישום ל-15 דקות + הצגת מפתח חד-פעמי).
  2. בדפדפן של המכשיר שנבחר בשלב 0 ‏#5, פתחו את ${ORIGIN}.
  3. במסך ההתחברות, תחת "הוסף passkey למכשיר חדש," הזינו את המפתח החד-פעמי המוצג ושם מכשיר כדי לרשום.
