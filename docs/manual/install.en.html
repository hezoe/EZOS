EZOS Installation Manual

This is a step-by-step guide for deploying EZOS on a new server (VPS) and making it available on a public domain. Anyone can build their own environment straight from GitHub.

This guide is written on the assumption that Claude Code will carry out the work. The operator simply logs in to the server over SSH, installs and authenticates Claude Code, and then instructs it: "Install this repository (github.com/hezoe/EZOS)." Claude then reads this document and performs the installation interactively. If you prefer to do it by hand, the same steps apply.

Architecture overview

Each installation consists of a single Node app + a systemd service + a Caddy site definition.

The browser connects through Caddy (TLS termination and reverse proxy) to the Node app listening on localhost. The terminal is bridged to a pseudo-terminal via node-pty + tmux, and claude runs interactively inside it.

STEP 1. Prerequisite commands

for c in git gh node npm jq tmux curl; do
  printf '%-6s ' "$c"; command -v "$c" || echo 'MISSING'
done
node -v   # v20 or later recommended
  • If anything is missing: sudo apt-get update && sudo apt-get install -y jq tmux curl
  • If Node is outdated or absent, install the Node 20 series.
  • Check GitHub authentication with gh auth status (run gh auth login if not authenticated).
  • Install Claude Code globally and authenticate with a Pro/Max account (~/.claude/.credentials.json).

STEP 2. Infrastructure check (Caddy / reverse proxy)

Decide on TLS termination and reverse proxying in this order: "first check whether one exists → use it if so, otherwise propose an approach."

command -v docker && docker ps --format '{{.Names}}' | grep -i caddy   # e.g. saas-caddy
ls -d /home/debian/saas/caddy/sites 2>/dev/null                        # site-definitions directory
  • If a Dockerized Caddy is running: you can publish just by adding a single sites/*.caddy file → go to STEP 6.
  • If there is no Caddy / a different proxy: if an existing nginx (or similar) is present, follow its conventions to forward <host> to 127.0.0.1:<port> and set up TLS. If there is no proxy at all, agree on an installation approach with the operator before proceeding (do not seize port 443 on your own).

STEP 3. Clone the repository

gh repo clone hezoe/EZOS "$APPDIR"    # or: git clone https://github.com/hezoe/EZOS.git "$APPDIR"
cd "$APPDIR/app"

STEP 4. Install dependencies & initial setup (generate config.json)

setup.js takes its values from environment variables (you must pass ORIGIN, RPID, and PORT). data/config.json is covered by .gitignore, i.e. it is per-installation runtime configuration.

cd "$APPDIR/app"
npm install --omit=dev

EZOS_ORIGIN="$ORIGIN" EZOS_RPID="$RPID" EZOS_PORT="$PORT" \
  node setup.js
# => creates data/config.json
For security, passkey registration is not accepted at all times. Only for the initial registration, run node bin/open-register.js on the server and register using the one-time registration key it displays (unlocked for just 15 minutes; automatically revoked on successful registration). From an already-logged-in device you can add passkeys without unlocking, via Settings → Passkey device management.

STEP 5. Run as a systemd service (auto-start, auto-restart)

KillMode=process stops only node, so that the tmux (persistent terminal) spawned by node-pty stays alive across restarts. So that requests from the Dockerized Caddy arrive via host.docker.internal, EZOS also listens on docker0 (172.17.0.1), which is why After=docker.service is added.

sudo tee /etc/systemd/system/${SERVICE}.service >/dev/null <<UNIT
[Unit]
Description=EZOS (${HOST}) - Claude web cockpit
After=network-online.target docker.service
Wants=network-online.target docker.service

[Service]
Type=simple
User=${USER_}
WorkingDirectory=${APPDIR}/app
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=3
KillMode=process
Environment=NODE_ENV=production
Environment=HOME=/home/${USER_}

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable --now ${SERVICE}
systemctl is-active ${SERVICE}          # => active
ss -tlnp | grep ":${PORT}"              # => node listening on 127.0.0.1:<port>

STEP 6. Caddy site definition (publish)

cat > /home/${USER_}/saas/caddy/sites/${SERVICE}.caddy <<CADDY
${HOST} {
  header {
    Strict-Transport-Security "max-age=31536000; includeSubDomains"
    X-Content-Type-Options "nosniff"
    X-Frame-Options "DENY"
    Referrer-Policy "strict-origin-when-cross-origin"
    Permissions-Policy "geolocation=(), microphone=(self), camera=()"
    -Server
  }
  encode zstd gzip
  reverse_proxy host.docker.internal:${PORT} {
    flush_interval -1
  }
}
CADDY

docker exec saas-caddy caddy validate --config /etc/caddy/Caddyfile
docker exec saas-caddy caddy reload   --config /etc/caddy/Caddyfile
  • flush_interval -1 streams SSE/streaming (Claude output) without buffering.
  • microphone=(self) in Permissions-Policy is for voice input (the Web Speech API).
  • After the reload, Caddy automatically obtains a Let's Encrypt certificate for ${HOST} (this assumes the DNS from #4 resolves to the IP in #1).

STEP 7. Session-tracking hooks (optional, recommended)

If you want to track Claude's session state (waiting for confirmation, working, etc.), call ${APPDIR}/app/bin/ez-hook.sh <state> from each hook in ~/.claude/settings.json. The script obtains the destination port automatically from data/config.json (localhost only, no authentication required).

STEP 8. Verification and first passkey registration

getent hosts "$HOST"                                                   # => <IP> $HOST
curl -sS -o /dev/null -w "%{http_code} ssl=%{ssl_verify_result}\n" "$ORIGIN/"   # => 200 ssl=0

If you get 200 ssl=0, publishing succeeded. Next, register the first passkey.

  1. On the server, run cd "$APPDIR/app" && node bin/open-register.js (15-minute registration unlock + one-time key display).
  2. On the browser of the device chosen in STEP 0 #5, open ${ORIGIN}.
  3. On the login screen, under "Add a passkey for a new device," enter the displayed one-time key and a device name to register.

Troubleshooting

SymptomWhat to check
curl returns 502/522systemctl is-active ${SERVICE} and ss -tlnp | grep :${PORT}. journalctl -u ${SERVICE} -e
No certificate is issuedWhether getent hosts ${HOST} returns the server IP (DNS not yet propagated). docker logs saas-caddy
Cannot register a passkeyWhether origin in config.json exactly matches the access URL, and whether rpID is the host's parent domain. Whether the registration window is open (node bin/open-register.js)
Not listening after a restart / EADDRNOTAVAILEZOS started before Docker and docker0 was not yet created. Check After=/Wants=docker.service in the unit. server.js retries automatically (retrying in 3s in journalctl)
